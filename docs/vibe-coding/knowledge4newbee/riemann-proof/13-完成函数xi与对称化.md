# 数学背景 13 — 完成函数 xi：被对称化的 zeta

> 面向零基础读者。读完你将理解为什么数学家偏爱 xi 函数：它把 zeta 的所有"瑕疵"修成完美对称。

## 1. zeta 的三处瑕疵

裸 zeta(s) 有三件麻烦事：

1. s = 1 处的极点（无穷大）
2. s = 负偶数处的"平凡零点"（来自 Gamma 因子，与素数无关）
3. 函数方程左右两边不对称（形式复杂）

## 2. 完成函数的修复术

乘上 Gamma 因子做"对称化"：

completed zeta(s) = pi^(-s/2) · Gamma(s/2) · zeta(s)

修复效果：

- 极点仍在 s=1（这个修不掉，它就是素数定理的内容）
- 平凡零点被吸收（Gamma 的极点抵消 zeta 的负偶零点）
- **获得完美对称**：completed(s) = completed(1 − s)

（进一步乘 s(s−1) 去掉极点，得到整函数 xi(s) = xi(1−s)——Riemann 本人的研究对象。）

## 3. 对称性如何简化零点证明

本引擎的两份装配（解读 13）都用这个对称：

- 在右半带（Re > 1/2）：直接由"非零定理"（EveryCharacter 的主特征情形）
- 在左半带：completed(s) = completed(1−s) 镜像到右半带 ⇒ 非零
- 在临界线上：正是要证明的结论

相比"cos 零点分类"版（CritLine 的逐因子检查），对称版把冗长计算藏进一个引理（completedRiemannZeta_one_sub）——两份装配正是同一思想的两种封装。

## 4. 类数与临界情形：为什么会有"类数三"文件

数域 K 的类群大小 h(K) 有著名的最小值问题。虚二次域的类数问题（Gauss 猜想的 Heegner 解）是"类数 = 1 的域恰有 9 个"这类**有限分类**的典范。类数 3 及以下同样可分类。

引擎在临界层（MainTheoremsCritical）引入类数三文件，推测是**小 conductor/小判别式的边界情形需要逐一处理**——大机器（宿主/窗口）在极小参数处可能退化，需要手工枚举兜底。这是数学证明的常见模式：主定理管"一般情形"，临界件管"例外情形"。
