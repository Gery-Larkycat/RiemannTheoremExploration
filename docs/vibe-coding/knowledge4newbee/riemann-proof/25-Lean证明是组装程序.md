# 数学背景 25 — Lean 证明是"类型驱动的组装程序"

> 面向零基础读者。读完你将学会用"读程序"的方式读 Lean 证明——这是导航 17M 行代码的核心技能。

## 1. 定理 = 类型，证明 = 程序

Lean 里每个定理是一个**类型**（输入什么假设、输出什么结论），证明是填这个类型的**程序**：

theorem 名字 (假设列表) : 结论类型 := 证明程序

读证明就是"看程序怎么把假设变成结论"。

## 2. 四个高频组装模式（本项目实测）

1. **obtain（剥洋葱）**：解一层"存在量化"——"有宿主 H 满足十四条件"⟹ 拿到具体的 H 和十四条证据。supplyOfAdmOf 里 obtain 出现 10+ 次，每层剥开一个存在量词。
2. **by_cases（分叉）**：把情形二分（主/非主、q|N/否则、左/右）——每支独立处理。反射法证明就是三分支（左带/线上/右带）。
3. **数值簿记（nlinarith/linarith）**：把几条线性不等式组合出新界——常数链（C0/K/A/x1 = max 各下界）的推导全靠它。AI 特别爱用组合参数吸收所有边界余量。
4. **mono 单调传递**：noExc_mono / hv.mono / HostExW.imp——"界变小仍成立"类引理，把强结论降级为弱结论复用。

## 3. 为什么这对理解 17M 行至关重要

17M 行里 97% 是**引理的声明与组合**，而非计算。读懂模式后：

- grep 定位声明行（theorem/def）
- 跳过证明体（读声明即懂数学内容）
- 只在"结构不明"处读证明体的骨架（obtain/refine 的形状）

本项目 24 篇 walkthrough 全部用此法，验证可行。

## 4. "类型驱动"的哲学

经典论文写"显然……于是……"，读者要自己补步；Lean 强迫每一步都有类型依据。**AI 证明之所以能到 17M 行，正是因为它把每步都变成了可机械检查的组装**——人类读它时反而获得了前所未有的导航性（grep 友好、声明自包含）。

## 术语速查

| 术语 | 一句话 |
|---|---|
| obtain | 解存在量词，拿到具体对象 |
| by_cases | 二分情形 |
| nlinarith | 非线性算术自动证明 |
| mono 引理 | 单调传递通用件 |
| 类型驱动 | 假设-结论作为接口契约 |
